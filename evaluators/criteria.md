# 평가 기준

피드백 기반 점수·비용 측정의 수용 기준은 [REQ01](../docs/REQUIREMENTS/REQ01.md)에 있다.

과제 등록 시 `task.md`의 사용자 행동과 화면 요구사항을 각각 검증 가능한 항목으로 풀어 `tasks/<ID>/evaluation/`에 둔다. 항목마다 ID, 통과 조건, 검사 방법, 증거 위치를 먼저 정하고 모든 비교군에 같은 버전을 적용한다. 공통 기술 검사는 `tasks/shared/` 사양에서 가져온다. FE-01의 자동 품질 가중치와 합격 조건은 [REQ01 품질 계약](../docs/SPEC/REQ01/quality-evaluation.md)에 고정하며 실행 결과를 본 뒤 변경하지 않는다.

자동 검사가 놓칠 수 있는 조작 순서와 과제별 필수 기능은 [기능 누락 점검표](./functional-review.md)로 결과마다 확인한다. 추가 점검은 현행 자동 점수에 포함하지 않으며 시각 평가는 사용자가 별도로 수행한다.

비교 전에 동일 과제·입력 해시·모델·추론 수준·Runner 옵션을 확인한다. 조건이 다르면 비교를 중단한다. 실행 순서와 반복 번호는 기록하되 동일할 필요는 없다.

| 항목 | 판정 근거 | 현재 처리 |
| --- | --- | --- |
| 실행 완료 | `run.json`의 `status`, 종료 코드, 타임아웃 | Promptfoo의 실행 성공 검사. 과제 완성도 점수로 사용하지 않는다. |
| 시간·토큰 | Runner의 `durationMs`, `usage` | 원값을 비교 결과에 기록한다. 측정 누락은 `null`과 사유를 유지한다. |
| 요구사항·기능 | 과제별 `evaluation/`의 테스트·검증 기준 | FE-01의 F01–F08을 브라우저에서 자동 검사한다. 검사기가 없는 과제는 미평가. |
| TypeScript·빌드·ESLint | 같은 명령과 의존성 조건에서 얻은 검사 결과 | FE-01은 공통 기술 스택과 `pnpm install --frozen-lockfile`·`pnpm build`를 검사한다. 저장된 결과 재평가에서 `tsc --noEmit`과 평가기 고정 `typescript-eslint` 권장 규칙을 별도 검사한다. |
| 시각적 완성도·접근성·코드 품질 | 과제별 루브릭과 증거 | FE-01의 A01은 브라우저로 검사한다. 저장된 결과 재평가에서 Promptfoo `agent-rubric`이 소스 코드 품질을 채점한다. 초점 표시와 화면 유사도는 미평가. |
| Skill 등록·실제 활용 | 환경 manifest와 실행 추적 근거를 별도로 확인 | 설치 manifest가 실행 당시 해시와 맞으면 등록 목록을 기록한다. 실제 활용은 검증된 이벤트 판정이 없어 `unknown`. |

`FE-01`의 판정 조건은 [과제 평가 기준](../tasks/FE-01/evaluation/criteria.md)에 있다. 이전 FE-03 저장 실행은 원본 REST Countries ZIP 해시가 일치할 때만 새 FE-01 평가기로 재평가한다. 실행 기록의 과거 ID와 해시는 바꾸지 않는다. 이전 Browser extensions manager·FAQ 과제는 종료했으며 리뷰 기록만 역사적 자료로 보존한다. 시각 평가는 사용자가 직접 수행한다.

FE-01 피드백 모드에서는 F01–F08, A01, T01–T02의 11개 객관 항목이 모두 판정됐을 때 통과 비율을 `objective_diagnostic` 점수로 기록한다. 오류·미평가가 있으면 점수는 `null`이다. 실패 항목과 증거만 다음 수정 프롬프트에 전달한다. 이 점수는 자동 품질 총점이나 시각 평가를 대신하지 않는다.

제한 검증에서는 이 진단 점수의 기본 중단 기준을 50점으로 낮춘다. 도달 여부는 `diagnostic_target_reached`로 기록하고 전체 품질 `passed`와 구분한다. 점수 자체를 인위적으로 변경하지 않으며, 미평가 항목을 통과로 바꾸지 않는다.

브라우저 검사는 로컬 Chromium을 사용한다. 기본 실행 경로는 `/snap/bin/chromium`이고 다른 경로는 `PLAYWRIGHT_CHROMIUM_PATH` 환경변수로 지정한다. 브라우저를 시작할 수 없으면 해당 항목을 평가기 오류로 기록한다.

Promptfoo는 저장된 Runner 결과와 두 실행 모두 판정 가능한 객관 항목을 JSON으로 비교한다. 시간·토큰은 환경별 반복과 누락 수를 함께 기록한다. Codex를 다시 호출하거나 LLM 주관 평가를 자동으로 시작하지 않는다. 주관 평가는 `not_evaluated`로 분리한다.

별도 `pnpm run evaluate` 명령은 [REQ01 자동 품질 평가 계약](../docs/SPEC/REQ01/quality-evaluation.md)에 따라 저장된 산출물을 다시 검사한다. 기능 40·접근성 15·정적 분석 20·AI 코드 품질 25점과 필수 통과 조건을 적용한다. `compare`의 기존 진단 점수와 `evaluate`의 자동 품질 총점은 서로 다른 결과다. AI 호출은 명시적으로 `evaluate`를 실행할 때만 발생한다. `--skip-ai`는 비용 없는 검사이며 전체 점수를 산출하지 않는다.
