# REQ01 품질 평가 계약

## 적용 범위

FE-01 REST Countries의 저장된 실행 결과에 같은 평가기를 적용한다. `pnpm run evaluate -- --runs <run.json> [...]`은 구현 Codex를 다시 호출하지 않고, 결과물 스냅샷에서 기능·접근성·빌드·정적 검사와 AI 코드 품질 평가를 새로 수행한다. 추가 평가 호출의 비용은 구현 비용과 분리한다. `--skip-ai`는 무료 검증용이며 총점·합격을 만들지 않는다.

## 판정 기준

| 영역 | 최대 점수 | 증거 |
| --- | ---: | --- |
| 기능 | 40 | 과제별 Playwright F 항목 통과 비율 |
| 접근성 | 15 | 과제별 Playwright A 항목 통과 비율 |
| 정적 분석 | 20 | 공통 템플릿의 strict `tsconfig`를 확장한 평가기 설정으로 `tsc --project <평가기 설정> --noEmit` 성공 50%, 고정 `typescript-eslint` 권장 규칙의 ESLint 오류 0건 50% |
| AI 코드 품질 | 25 | Promptfoo `agent-rubric`의 0–100점 |

총점은 각 영역의 0–100 점수에 표의 가중치를 곱해 합산한다. 타입·린트 판정은 참가자가 수정한 설정 대신 평가기 고정 설정을 사용한다. 합격은 모든 영역이 판정되고 **기능 100%, 공통 기술 스택·빌드 통과, 타입 검사 통과, ESLint 오류 0건, 총점 90점 이상**일 때다. 검사 오류나 미평가 영역은 0점으로 대체하지 않고 총점 `null`, 합격 `false`로 남긴다. 시각적 유사도는 이 자동 점수에 포함하지 않고 별도 미평가로 표시한다. 사용자가 시각적 품질을 별도로 판단하며, [기능 누락 점검표](../../../evaluators/functional-review.md)의 추가 항목도 자동 점수와 구분한다. 이 점수는 시각 검토까지 끝난 전체 결과물 완성도와 구분한다.

## AI 코드 품질 루브릭

한 번의 `agent-rubric` 호출로 구현 소스를 열람한다. 세부 배점은 구조 25, 가독성 20, 유지보수성 25, 불필요한 복잡성 15, 책임 분리 15다. 각 영역은 심각한 결함 0%, 중대 결함 약 25%, 장단점 혼재 50%, 경미한 문제만 있음 75%, 명확하게 좋은 설계 100%를 기준으로 해당 영역 최대점수 안에서 정수로 채점한다. 평가 사유에는 **각 영역의 획득점, 파일·줄, 긍정 또는 부정의 구체적 근거**를 기록한다. 영역 이름과 근거가 빠지면 AI 채점을 오류로 처리한다. 장식적 추상화나 파일 개수만으로 가점을 주지 않는다.

평가 모델은 `gpt-6.1-sol`, 추론 수준 `medium`, Promptfoo `0.126.0`, Codex SDK `0.167.0`, AI 코드 루브릭 버전 2로 고정한다. 버전 1의 명령 전면 금지는 모델의 소스 열람을 막아 실제 평가에서 오류로 판정됐다. 버전 2는 작업 디렉터리 안의 읽기 전용 명령만 허용한다. 결과 파일에는 해당 설정과 원본 코드 SHA-256, AI 판단 사유·토큰 사용량을 보관한다. 평가용 Codex는 별도 홈, 읽기 전용 sandbox, 승인 없음, 네트워크·검색 비활성화로 호출한다. 평가 복사본에서 원본 `AGENTS.md`·`CLAUDE.md`·Skill·평가 자료·정답·민감 파일을 빼며, 평가 전후 해시를 비교해 변경을 감지한다. 평가기는 비교군 ID를 프롬프트로 전달하지 않는다. 파일 시스템의 완전한 보안 격리를 보장하는 방식은 아니며, 지침·입력·쓰기 경로를 분리한 절차적 격리다.

## 결과와 재평가

각 `run.json`에는 시도 직후 보존한 `artifact` 경로와 SHA-256을 남긴다. 피드백 수정 시도마다 별도 스냅샷을 만들어 첫 시도 코드가 후속 수정으로 바뀌지 않게 한다. 이전 기록처럼 스냅샷이 없는 실행은 기존 `workDir`에서 평가하며 현재 파일을 복사해 평가한다. [Runner 결과 경로](../../../runner/README.md#작업-폴더와-저장된-결과)의 `evaluation.json`에 과제·환경·시도, 구현 `usage`, 평가기 `tokenUsage`, 둘의 분리된 합계, Playwright 체크, 타입·ESLint 상세, AI 근거, 영역별 점수, 총점·합격을 저장한다. 평가 비용은 새 재평가마다 새 결과로 남기고 과거 구현 토큰에 합치지 않는다. 비교군 간 점수 비교는 동일 루브릭 버전·모델·설정·과제·입력 해시의 결과끼리만 한다.

## 검증 상태

이전 FAQ 제한 검증의 실제 AI 평가 기록은 [Phase02 검증 기록](../../REVIEW/REQ01/Phase02.md)에 역사적 증거로 보존한다. 현재 FE-01의 기능 8개·접근성 1개·기술 2개는 저장된 두 REST Countries 결과물에 같은 외부 평가기로 적용한다. AI 코드 평가와 사용자의 시각 평가는 각 결과에 대해 별도로 기록한다.
